## Overview

This directory hosts the application's central state implementation for the OpenPlanter desktop frontend. At the root it contains a single TypeScript module that defines a simple observable state store along with the shape of the application state. The file is intended to be the canonical location for state access and updates in the frontend, providing a shared, typed store that UI components can subscribe to and modify.

Because there are no subdirectories, the directory is intentionally compact: the provided store.ts is the single source of truth for state logic within this folder. Other frontend modules import from this file to read or react to state changes. In the larger system, this directory's role is to encapsulate state shape and the observable store mechanism so that UI layers can remain focused on presentation while relying on a typed, centralized state implementation for data and change notifications.


### File Organization

A single-file flat layout: store.ts contains both the observable store implementation and the application state type definitions. This keeps state logic centralized and easy to find for developers working on front-end state management.

## Architecture Notes

- Centralized observable store pattern: a single file provides the store instance and state shape so UI code can import a shared source of truth.
- Type definitions for the application state are colocated with the store implementation to ensure type safety and reduce drift between state structure and usage.
